# 后端核心整改复验记录 v0.3

日期：2026-09-05  
对象：`E:\ai-customer-service-plan\开发\backend`  
依据：《后端开发文档 v0.1》及后端 v0.2 代码审计问题清单

## 结论

v0.2 审计中的核心一致性问题已完成本轮整改并在 SQLite 隔离环境复验：登录后的 CSRF 刷新可继续写入；SSE 每段正文在发送前已落库；删除意图先阻断内容并由独立日志按连续序号投影；Worker 以 `claim_version` 防止过期执行者落库；任务分页使用 `(created_at,id)` 游标；readiness 要求两组迁移与日志水位均就绪。

该结果不替代 PostgreSQL 并发、真实 HTTP 断流、供应商调用、备份恢复和完整 V1 验收。

## 整改结果

| 原问题 | 状态 | 实现与复验 |
| --- | --- | --- |
| 登录后 `/auth/csrf` 返回预认证 token | 已关闭 | 已登录请求返回当前 session CSRF；回归测试用刷新后的 token 创建会话成功。 |
| SSE 先发正文、后持久化 | 已关闭 | 每个片段更新 run 的正文、版本和序号并提交后才发送；完成事件同样先提交终态，并在发送前复核 epoch、删除和服务状态。 |
| 日志确认后业务库失败会遗留可见内容 | 已关闭 | 新增 `deletion_intents`、`journal_projections`；先提交阻断意图，独立日志后按连续 `applied_seq` 创建 receipt/job。日志孤儿条目复验可重建最小清理任务并封锁会话。 |
| Worker 缺少领取版本栅栏 | 已关闭 | 领取返回 `JobClaim`，最终写入校验 `claimed_by`、`claim_version` 和租约；加入心跳、领取上限和退避。回归测试验证旧 claim 无法结束被重新领取的 job。 |
| `assistant_id` 静默丢弃 | 已关闭 | 会话响应显式返回绑定字段；助手版本模块实现前，提供 `assistant_id` 返回 `assistant_binding_unavailable`，不再伪造绑定成功。 |
| 任务游标按 UUID 过滤 | 已关闭 | 使用已签名的 `created_at,id` 复合游标；UUID 顺序与创建时间相反的回归场景通过。 |
| readiness 未核验迁移和恢复 | 已关闭 | 检查 B002/J001 Alembic revision 与每个 workspace 的 `applied_seq=head_seq`；仅 `create_all` 的库返回 503。 |
| 进程内登录限流无边界 | 已关闭 | 限流状态改存业务库，以脱敏哈希键表示来源和用户名；回归测试验证阈值后返回 429。 |
| 过期会话撤销回滚 | 已关闭 | 检测到过期后先提交 `revoked_at`，再返回 401。 |
