## 1. 结论

**当前前端不能按“已完成提示词设计且可交付”验收。** 已有 7 个客服模块、身份选择和功能规划页面；它们是深色交互原型。用户要求的星球视频首页及单文件 HTML 尚未生成，标准构建失败，另有连接状态竞态和样式遗漏。

本次发现 **2 项 P1、3 项 P2**。P1 是当前交付阻塞，P2 是交互、可用性及回归检查缺陷。没有发现应定为 P0 的问题，但这不代表完成安全审计。真实模型、认证、持久化与后台任务尚未接入，不把这些已明确的阶段边界冒充新发现的生产漏洞。

用户提出“审计”后暂停新增应用页面；本报告检查这一时点的代码。审计期间只新增复核脚本、截图、报告并同步事实状态，没有修复下列应用问题。

## 2. 问题清单

### FE-A01 · P1 · 星球首页及单文件交付缺失

- **证据：** [应用入口](E:/ai-customer-service-plan/开发/frontend/index.html:11)加载 Vue 模块；[路由](E:/ai-customer-service-plan/开发/frontend/src/router.ts:7)默认进入聊天。工程没有 public/space.html。现有[设置页](E:/ai-customer-service-plan/开发/frontend/src/views/SettingsView.vue:21)、[登录页](E:/ai-customer-service-plan/开发/frontend/src/views/LoginView.vue:10)等却已提供星球首页链接。
- **复现：** 访问 /space.html。在本次 Vite 开发环境被 SPA 回退处理，实际地址为 /space.html#/chat；videoCount = 0，planetSlots = 0。未出现星球首页。正式静态部署的失败形式取决于服务器回退规则，不能推断为一定返回 404。
- **差异：** 尚无指定星球视频／海报／透明切图、EARTH → VENUS → MARS 切换、指定衬线字体、--u 构图比例、一次性入场动画、背景静帧降级与单文件独立入口。当前深蓝与青色配色只是部分视觉迁移。
- **影响：** 核心设计要求没有交付，已有导航指向不存在的目标。
- **整改：** 先实现可独立打开的首页 HTML，并统一所有首页入口；保留客服文案和模块入口的改编说明。客服工作台继续使用 Vue 不等于首页可免构建运行。
- **复验：** 直接打开 HTML 能显示首页；服务地址和各返回入口正常；三颗星球可逆切换；素材切换不改写侧槽 img.src；移动布局及 reduced-motion 检查通过。提示词要求的 <2ms 切换应实测，不能用代码推断宣称通过。
- **状态：** 未整改。

### FE-A02 · P1 · 标准构建被 TypeScript 工具兼容问题阻断

- **证据：** [package.json](E:/ai-customer-service-plan/开发/frontend/package.json:24)与锁文件安装了 TypeScript 7.0.2、vue-tsc 3.3.11。
- **复现：** 项目目录执行 pnpm build，退出码 1。vue-tsc 尝试访问 TypeScript 的 ./lib/tsc，但该包没有导出此子路径，报 ERR_PACKAGE_PATH_NOT_EXPORTED。
- **影响：** 类型检查尚未真正完成，不能声称正式构建成功，也不能排除后续类型错误。
- **隔离结果：** 单独执行 vite build 成功，只证明此次打包步骤可以完成。开发服务器能显示页面也不能抵消标准构建失败。
- **整改：** 选取经兼容验证的 TypeScript 与 vue-tsc 版本组合，更新锁文件；保留类型检查，不以移除检查绕过问题。
- **复验：** 按锁文件安装后 pnpm build 完整退出 0，并处理实际暴露的类型错误。
- **状态：** 未整改。

### FE-A03 · P2 · 过期的连接测试结果污染新配置

- **证据：** [ConnectionView.vue](E:/ai-customer-service-plan/开发/frontend/src/views/ConnectionView.vue:9)启动测试后等待 550ms，再无条件调用 [testConnection](E:/ai-customer-service-plan/开发/frontend/src/stores/workspace.ts:205)，它把当时的当前配置设为 tested = true，没有绑定被测试配置的版本。
- **复现：** 点击“模拟连接测试”，立即把地址改成 https://changed.example.com/v1 并保存。旧测试结束后，新地址被标为 tested = true。
- **本次实测：** savedBaseUrl = https://changed.example.com/v1；tested = true。新保存配置没有获得针对自身的测试结果，却显示“模拟可用”。
- **影响：** 预览中连接状态错误，并影响 startReason 的发送准入；将此逻辑直接接到真实接口，会继续产生错误状态。
- **整改：** 测试绑定不可变配置快照及请求序号；保存新配置时递增版本，旧结果不得回写。卸载或身份变化时取消／忽略尚未完成的请求。只禁用重复测试按钮不足以解决问题。
- **复验：** 测试 A 期间保存 B，A 的成功或失败均不改变 B；B 在自己的测试成功前保持未测试；离开页面后的旧结果不得更新新连接。
- **状态：** 未整改。

### FE-A04 · P2 · 助手配置标签缺少样式，文字几乎不可读

- **证据：** [AssistantView.vue](E:/ai-customer-service-plan/开发/frontend/src/views/AssistantView.vue:18)的 .section-tabs 使用未套用 .tab／.button 的原生按钮；[view-styles.css](E:/ai-customer-service-plan/开发/frontend/src/view-styles.css:2)仅定义了外层尺寸和间距，没有定义标签按钮。
- **复现：** 打开助手配置。基础配置／版本记录为浅色原生按钮，继承了深色主题下的浅色文字。
- **本次浏览器计算值：** 背景 rgb(240,240,240)，文字 rgb(214,229,239)，字体 14px，按钮高 25px；按 sRGB 相对亮度计算对比度约 1.13:1。截图也可直接看出文字难辨。
- **影响：** 用户难以识别与切换配置页和版本记录页；活动状态缺少清楚的视觉呈现。
- **整改：** 使用统一的深色标签组件，补齐普通、选中、悬停和键盘焦点状态，并明确当前页语义。
- **复验：** 两个标签在桌面／手机均清晰可读，可通过键盘操作，当前选中项具有可见且可访问的状态。
- **状态：** 未整改。
