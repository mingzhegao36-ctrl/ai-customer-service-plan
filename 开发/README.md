## 按任务读取与验证

局部任务从受影响文件和工程说明进入。接口任务读相应契约；数据库任务读模型、迁移及事务约定；权限、预算、流式发布、Worker 或删除任务读对应不变量与故障案例。产品范围或交付任务再读相关 PRD、AC／NF 和阶段门。无需每次通读全部主文档。

| 触发任务 | 所需验证 | 完成边界 |
| --- | --- | --- |
| 文档、规则、导航 | 校对改动条款及受影响的本地链接；含命令时核对工程入口 | 无业务行为变化时不跑应用构建、单测或 e2e |
| 前端文案、样式、布局 | 受影响页面的可见结果；源码变更执行 `pnpm build`；影响响应式时检查相关断点 | 无状态逻辑变化时不补镜像式单测；无需采集全部页面 |
| 前端状态、路由、交互 | `pnpm build`、受影响的 Vitest 与 Playwright 用例；共享状态或路由变更扩大到相关流程 | 依赖或构建配置变更执行完整构建与回归；不重复单独运行 build 已包含的 vue-tsc |
| 后端 Python 实现 | 受影响的 pytest 用例、Ruff 与 Mypy；共享依赖或全局行为变化扩大回归 | 验证具体输出与失败路径，不只看代码可导入；compileall 无需每次与已有检查重复 |
| 模型、索引、迁移 | 隔离库的空库及上一版本升级、相关数据回填检查；对受影响库执行 `alembic check` | PostgreSQL 特有行为必须在真实 PostgreSQL 验证；未变更另一组库时无需重复其迁移 |
| 鉴权、预算、SSE、Worker、删除恢复 | 相关越权、竞态、幂等和故障回归；锁与事务用真实 PostgreSQL，断流和撤权用实际 HTTP 入口 | SQLite／ASGI 检查可作早期反馈；不能单凭这些关闭依赖真实环境的审计项 |
| 冻结、交付发布包、V1 或后续阶段验收 | 对纳入范围的能力执行完整构建、回归、独立审计及适用 AC／NF；冻结包记录版本和哈希 | 负载、备份恢复、真实供应商、接手与准入证据按交付阶段落实；保持原性能和安全门槛 |

验证命令在各工程 README。目标测试可用路径或用例筛选；筛选范围要覆盖实际影响。API 变更在实现中维护并核对 OpenAPI／请求响应契约，提交该接口联调前确认兼容性；不要求写每段代码前完成整份 OpenAPI 或人工签核。

关键验证缺少环境时先完成可运行检查与必要测试用例，说明未验证的风险与所需条件；依赖该证据的完成项保留待验证。与任务无关的未实现模块不影响局部交付，适用验证失败则继续处理，不用已通过的检查代替失败项。
