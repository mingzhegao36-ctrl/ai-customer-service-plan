## 1. 执行与判定规则

测试前固定实际应用版本、需求基线、模型／预算／审核策略版本、输入样本、角色权限、环境及预期结果。V1 不要求交付未来模块；V2 扩展后必须重新验证受影响的预算、删除、上下文、身份和文件路径。

- **未执行：** 未运行或无证据；当前全部应用案例属于此状态。
- **通过：** 该范围的操作、预期和证据均满足，记录实际执行人与日期。
- **失败：** 已执行且结果不满足要求，关联问题及复验记录。
- **受阻：** 环境、接口或资料不足使案例无法执行，记录缺失项，不能算通过。
- **不适用：** 当前阶段确未启用该能力，记录范围依据及批准人；基础安全约束不能据此排除。

没有截图、日志、数据记录或其他适合该案例的证据，不签为通过。自动化测试输出、人工走查与真实供应商／业务联调分别标记；模拟成功不代表真实外部服务已接入。

正常负载的输入样本分布为 2,000—4,000 Token，输出任务目标为 200—600 Token，生成上限仍依预算策略。环境清单包括模型快照、供应商配额、资源、应用版本、输入哈希、生成参数、网络位置与脚本版本；公开档位另记审核器及策略版本。

分母 N 是测量窗口内符合认证和请求限制的全部逻辑提交，同幂等键只算一次。未成功建 turn 的 5xx、意外 429、网络中断、超时、重试耗尽和供应商错误仍留在失败分母。服务成功率计算预期非错误业务响应；完整回复率还要求有意义完整答案或约定澄清／转人工响应、合法终止事件及服务端保存一致。空答案、部分文字或异常终止不算完整。

首字从客户端提交到第一个可展示答案文字，完成到合法终止事件并确认保存一致。成功样本算 p95，失败数量和时长另表；任一成功率门槛失败，整体失败。主动取消、身份攻击、预算用尽、故障注入和超容量压力放独立组，不能看到失败结果后改组、改分母或降低阈值来判通过。

## 4. 质量、效果与运营标准

| 指标／检查 | 初始目标或要求 | 统计与证据 |
| --- | --- | --- |
| 业务回答正确率 | 固定业务集人工判定 ≥ 90% | 初始建议 50—100 题，记录逐题事实、步骤、依据与错误；分场景报告，权限／注入／故障另建集合 |
| 资料与兜底 | 政策答案有有效且可访问来源；无依据、高风险样例正确澄清或转人工 | 审核 FAQ、版本／有效期、引用与人工评分；相似度不代替答案正确率 |
| AI 独立有效解决率 | 扩量初始目标 ≥ 40% | 以成熟、分配到 AI 的范围内问题为分母；无人工接管，有用户确认或可核实完成事实，观察期内无重开／需纠正后果 |
| 成本护栏 | AI 路径每有效解决成本 ≤ 同范围人工基线的 70% | 全部生成、审核、检索、失败及重试支出纳入；另外报告 AI＋人工整体成本；无真实基线不能判达标 |
| 评分护栏 | 有帮助率 ≥ 80%，评分覆盖率 ≥ 20% | 最新评分去重，未评分不算满意；有帮助率与覆盖率分别给原始分母 |
| 人工响应 | 服务时段正式受理的人工请求 5 分钟内接起比例 ≥ 90% | 分母含超过时限未接起和放弃；服务时间内外分别报告，不用无值班时间充当实时服务 |
| 重大问题 | 阶段准入范围内重大数据／权限事故和重大错误承诺为 0 | 全部事件及投诉登记；出现时按运营手册停用处置，不只看平均正确率 |
| 知识与反馈运营 | 每周至少抽检 50 个问题，不足全检；知识每月全量复审，时效政策变更当天处理 | 分层抽样，投诉另外全查；问题分派、期限、发布与复测可追踪 |
| 移动与可访问性 | V2 覆盖 360／390／768 像素及键盘、触屏、读屏核心流程 | 沿用原 PRD 的可访问性目标；走查证据不冒充认证 |

问题成熟期为首次提交超过 72 小时；沉默、失联、未完结仍在分母，人工接管不能算 AI 独立解决。相同问题重开需关联并回写原队列结果；匿名无法可靠关联时说明限制。给出样本量、场景分布、原始分子分母及区间估计，不只报一个百分比。

以上属于 v1.3 的初始决策标准，正式试点前按实际业务冻结；未达到样本条件或没有成本证据时写“证据不足”，不写达标。

## 5. 阶段验收与扩量条件

| 阶段门 | 应交付的证据 | 判定角色 |
| --- | --- | --- |
| G0 责任到位 | 产品、开发、客服、知识、财务、法务及维护替补的实际姓名和职责 | 发起人 |
| G1 立项与范围 | 实际场景、方案比较、预算、基线／补采计划、Must 范围、目标与依赖；不足仅可批准有上限 V0 | 发起人＋产品＋财务及相关负责人 |
| G2 V1 内部验收 | 当期 Must、对应 AC／NF 和原审计案例；3—5 位内部用户至少 5 个工作日试用；备份恢复、停用回退、接手与未解决问题记录 | 产品＋开发＋内部使用者／维护人 |
| G3 V2 外部准入 | V2 功能及公开审核档位、对应审计测试、知识题库、C01—C07 适用证据、真实服务文案、排班和降级演练 | 产品＋客服＋开发＋内容安全／法务 |
| G4 逐档扩量 | 当前档位质量、成本、样本量与观察期均达标，分组可追溯，人工容量和回退可用 | 产品＋客服＋财务及发起人 |

| 档位 | 最低观察和样本 | 进入下一档 |
| --- | --- | --- |
| 外部种子 | G3 后 20—50 位客户，至少 7 天且 ≥ 100 个成熟范围内问题 | 关键流程无阻断、无重大事件，只能进入 5% 继续验证 |
| 5% 合格入口 | 至少 14 天，AI 组 ≥ 200 个成熟问题，同期人工对照 ≥ 100 个 | 同时满足产品护栏、成本和评审要求后进入 25% |
| 25% 合格入口 | 至少 14 天，AI 组 ≥ 500 个成熟问题，同期人工对照 ≥ 100 个 | 各主要场景达标、人工容量及降级通过后决定 100% |
| 100% 冻结范围 | 仅覆盖已批准范围，持续日看周审 | 不自动扩展到其他行业或业务 |

样本不足延长观察，不按日期自动放量；分组按主体／会话稳定保持，不能通过重试或新登录任意换组。严重事件立即降级；正常请求最近 15 分钟至少 100 个且失败率 > 5%、预算用尽或发布授权失效，按原 PRD 暂停新 AI；低流量仍可人工停用。连续两天产品护栏不达标停止扩量并调查。

## 7. 验收记录格式

每次实际验收在“审计”保存报告、在“归档”保存冻结证据；“开发”保存可重复运行的测试。执行结果同步[产品状态](E:/ai-customer-service-plan/产品/产品状态.md)。

| 字段 | 必填内容 |
| --- | --- |
| 编号与对象 | AC／NF／原审计编号、关联 FR、阶段与实际范围 |
| 基线 | 需求／技术版本、代码版本、模型、预算和审核策略 |
| 环境与输入 | 部署资源、身份角色、样本／脚本版本、供应商配额、是否模拟 |
| 执行 | 操作、预期、实际结果、原始日志／截图／数据位置 |
| 结论 | 未执行／通过／失败／受阻／不适用；失败或不适用必须写原因 |
| 人员与时间 | 执行人、评审人、实际日期；不填虚构姓名 |
| 后续 | 问题编号、修复版本、复验日期与结果 |
