# 产品决策

文档版本：v1.0 · 编写日期：2026-09-05 · 状态：产品工作稿，业务待决事项未签核

依据：[开发文档／技术设计 v1.3](E:/ai-customer-service-plan/AI智能客服系统开发文档.md)、[原 PRD v1.3](E:/ai-customer-service-plan/AI智能客服系统-产品需求文档PRD.md)、[运营手册 v1.3](E:/ai-customer-service-plan/AI智能客服系统-运营手册.md)。

本文记录为什么选择当前范围、哪些方案已写入基线、哪些事项仍需业务决定。它是 v1.3 的决策工作视图；不替代原 PRD，不把用户授权编写和修改文档当成立项、采购或公开上线批准。

## 1. 当前方向

建设一个由管理员配置 API Key 的 AI 聊天与客服系统，逐步具备对话管理、知识检索、人工协作和受控业务能力。先验证服务效果与总成本，再决定是否投入微调。

当前计划顺序为 **V0 技术验证 → V1 内部聊天与数据管理 → V2 知识库与人工客服试点 → V3 业务工具 → V4 按效果决定训练实验**。阶段编号表示能力范围，不表示完成进度。

## 2. 已纳入文档基线的决策

以下“已采纳”仅表示已写入现行方案；实际实施仍需相应阶段的条件与验收。

| 编号 | 当前决策 | 原因及代价 | 关联需求／依据 |
| --- | --- | --- | --- |
| PD-01 | 先做一个真实范围的内部工具，再开放客服试点 | 先验证聊天、数据与费用闭环；真实行业未定时只用测试数据做 V0 | FR-00、FR-20；技术 3；PRD 1、4 |
| PD-02 | 首版单团队、一个助手模板、一个供应商适配器、简体中文独立网页 | 限制首期复杂度；多供应商同时接入、挂件和多语言另排期 | FR-01、FR-18；技术 3.2；PRD 4 |
| PD-03 | 管理员带 Key，普通聊天用户不接触供应商凭据 | Key 在服务端保护、轮换和审计；每位用户自带 Key 是后续独立功能 | FR-01；技术 3.2、13.1 |
| PD-04 | 完整账本和服务端预算是 Must，图形看板可延期 | 成本要包含辅助调用、失败与重试；未知费用占用余额，不能以取消或超时清零 | FR-08、FR-13；技术 14.2 |
| PD-05 | 只重试末轮，保留唯一有效完整答案 | 防止历史分支混乱和重试重置预算；新答案失败时仍保留原有效答案 | FR-03、FR-04；技术 6.1—6.3 |
| PD-06 | 检测断流后尽力终止；刷新查询快照，主动重试才新生成 | 首版不建设断线后继续生成与事件补传；用户能确认真实状态，但不承诺上游立即停费 | FR-02、FR-05；技术 6.6 |
| PD-07 | 业务事实先用知识库，实时个人信息用受控接口 | 聊天保存和文件上传都不等于模型训练；变化的事实不依赖微调记忆 | FR-14、FR-21、FR-22；技术 9—11 |
| PD-08 | V2 公开答复全文审核后展示，所有读取入口共用可见性规则 | 降低历史、导出、摘要绕过审核的风险；审核增加费用和等待时间，公开档位单独验收 | FR-15、FR-18；技术 6.7、12、14.2 |
| PD-09 | 删除凭证独立持久保存，文件和后台任务有恢复协议 | 业务库回退不能让已确认删除数据重新可见；增加独立日志、运维和故障测试投入 | FR-06、FR-07、FR-10；技术 5.5、6.4—6.5、8.4、13.6 |
| PD-10 | 人工请求受理后立即停止新的 AI 回复 | 排队时也不让 AI 继续插话；必须有实际值班、渠道与真实服务承诺 | FR-17；技术 10.2；PRD 6.2 |
| PD-11 | 训练和长期记忆默认关闭，只有合格数据和收益证据才推进 | 避免把原始聊天直接当训练资产；训练资格、数据用途和模型发布均需独立验证 | FR-19、FR-22；技术 11、13 |
| PD-12 | 新产物按七个工作目录归类，现有主文档保留原路径 | 保持历史链接与版本证据；本目录新增主题视图和追踪编号，详规不建立重复权威副本 | 本目录四份文档；工作区 README、AGENTS.md |

## 4. 范围取舍和投入决策

V1 Must 保留登录隔离、模型连接、聊天及断流恢复、历史删除、预算账本、版本撤销、后台任务、授权导出、观测停用、备份与接手。评分及完整配置界面为 Should；自助导出、搜索、图形看板等为 Could。具体条目见[产品需求](E:/ai-customer-service-plan/产品/产品需求.md)。

按原 PRD 执行两类不同阈值：

- **工作包取舍：** 超过批准工作包投入 20%，先移后 Could，再移后复杂配置界面，必要时后移评分 UI；Must 无法交付则重新排期或止损，保留权限、预算、删除一致性及验收。
- **路线重评：** 预计总投入超过批准上限 30%、预计回收期超过 12 个月且没有获批的非财务价值、无真实试点需求／资料负责人、无接手保障或公开条件不能满足时，暂停新增自研范围并记录继续、缩小或采购的决定。
- **试点止损：** 连续两轮、每轮至少 14 天并达到样本门槛的改进后仍未达扩量条件，停止扩量并重评；样本持续不足时最长观察 6 周后作继续小规模验证或停止的决定。

自研与其他路线先核验必需条件，再按 12 个月总成本 25、流程适配 25、数据控制迁移 25、交付速度 15、维护接手 10 评分；没有证据记未验证，不能靠高总分抵消权限或数据控制缺口。

现行规划为 V1 Must 33—52、V2 27—42、V0 2—4 开发人日；V0—V2 合计 62—98，20% 缓冲后 75—118。可选项及 16—29 非开发人日另列。原 PRD 的财务示例不是报价；正式成本、预算与日历仍待 O-03／O-05 确认。

## 5. 决策如何生效和变更

一项待定事项完成时，在本文件补齐实际决定、适用范围、依据、决定人、日期及替代的旧决定；同步原 PRD／技术设计与受影响的 FR、AC 和产品状态。具名决定与真实证据尚缺时保持待确认，不通过填写计划日期来宣称已经生效。

| 记录字段 | 填写要求 |
| --- | --- |
| 决策编号与状态 | 保留 PD／O 编号；拟议、已决定、被替代分别标记 |
| 结论与适用版本 | 明确何时、对哪些入口或功能生效 |
| 依据与决定人 | 访谈／验证／预算／评审证据及实际姓名、日期 |
| 影响 | FR、AC、成本、日历、数据用途和运营流程 |
| 后续动作 | 实施负责人、预计完成时间和验证方式 |
